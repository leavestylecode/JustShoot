# 17 款风格的离线场景评估 · 2026-10-25

本轮完成肤色、日光、夜景的离线逐款检查和共用渲染器修正。**没有改写任何 LUT 的颜色表，也没有完成多场景 iPhone RAW 对拍校准。** 用户目前无法配合摆拍，因此将可以离线验证的技术一致性与需要实拍确认的相机成像差异分开记录。

本轮最明确的改善是颗粒：过去较小预览仍给每个像素施加接近完整照片的颗粒，缩略显示时明显偏重；新的幅度匹配使预览更接近完整成片缩到相同尺寸后的颗粒感。新拍摄也统一使用不额外抬灰、不改变肤色均值的颗粒响应。旧拍摄任务继续恢复其冻结的旧配方。

## 数值如何解释

夜景 LUT-only 的近黑比例，定义为三个 sRGB 通道均不高于 `1/255`：原图以 `report.json` 为准；Velvia **55.58%**、Classic Chrome **47.59%**、ACROS **37.60%**、PROVIA **22.91%**、PRO Neg. Std **15.35%**、ETERNA **5.29%**。它说明这张已经偏暗的 SDR 照片再经过 LUT 后，哪些风格收紧了暗部；不说明整个图像链路出现了此前“RAW 全黑”的故障。

Portra、400H、Phoenix 等近黑比例为零，原因之一是 LUT 本身带有非零、有色黑位。抬黑可以形成审美上的柔和感，但不是恢复真实暗部信息。新版颗粒只去除颗粒自身额外造成的偏置，保留 LUT 自己的这些黑位。

四个肤色探针只是在 sRGB 中定义的不同明度 RGB 色块，不是实测 ColorChecker、不是四个人种的光谱肤色。报告中的 Lab 明度差、色度比例和色相变化均相对输入计算，不能当成对真实胶片的 ΔE 准确度。极暗、近无彩色探针的色相角很不稳定，不作为错误判定依据。

1025 级中性灰阶可检查明显反转；少数社区/模型派生 LUT 的 toe 有细小起伏。报告同时给出累计最大回落，而不只统计下降步数，避免把小于一个 8-bit 色阶的变化夸大成严重反转。本轮没有为消除这些微小起伏而改写颜色表。

## 已接入的修正

1. 新建 `FilmGrainSampling`：用 4000 像素参考画幅的颗粒面积平均方差估计缩略颗粒幅度。共享 CI/Metal 参数，无图像读回、无额外 GPU pass；尺寸/参数缓存最多 128 项。
2. 新拍摄的有颗粒风格和自定义 LUT 使用 `balanced_area_v3`。保留原 amount、size、chroma，同时避免旧颗粒给阴影加灰、给肤色均值增加偏置。历史无版本/v2 任务保持原样恢复。
3. 预览 LUT 输入直接采样为 float，去掉查表前一次多余的 half 舍入。在同一输入/同一精度的整图比较中，最大 CI/Metal 差从约 `0.002782` 降至 `0.002225`，即约 **0.71 → 0.57 个 8-bit 色阶**。这不是提高摄像头源位深，也不是实拍预览/RAW 差异测量。
4. LUT 准备期间的预览回退参数也从统一的 `captureRenderProfile` 读取，避免短暂恢复旧色温响应或旧颗粒。
5. 新增整图回归：17 款 × 三类合成压力图；提供场景目录时，再覆盖三张真实 SDR 照片。直接运行实际 Metal `previewLUT` 与 CI 调色阶段，并用独立 CPU 三线性插值探针交叉核对。逐款成片导出含后续颗粒/光学。

颗粒基准以同一完整图像分别缩小 2、4、8 倍为参考，测试尺寸 1 / 1.235 / 2。旧预览标准差为参考的 **1.07–4.53 倍**；修正后为 **0.996–1.012 倍**。这证明了这组均匀色块、固定种子和面积平均条件下的方差匹配，不代表不同缩放滤镜、所有纹理与不同随机种子的像素能逐点重合。

验证的精确次数、日志、逐款误差和资源哈希见同目录 `offline-scene-validation.json` 与 `offline-scene-metrics.json`。没有测量物理设备帧率，因此不声称本轮有真机性能提升。

## 输入来源与边界

- 肤色：[scikit-image astronaut / NASA Eileen Collins](https://scikit-image.org/docs/stable/api/skimage.data.html#skimage.data.astronaut)。实际人像只有一位浅肤色人物，深肤色只做合成探针压力检查。
- 日光：[Kodak Image 19 / Alan Fink](https://r0k.us/graphics/kodak/kodim19.html)。这是 EKTACHROME 64 Pro 的 PhotoCD 派生图，已有胶片和扫描影调；无标记源按 sRGB 解释，不能用它证明日光白平衡或某款胶片的绝对准确性。
- 夜景：[2011-03-11 night in Taipei](https://commons.wikimedia.org/wiki/File:2011-03-11_night_in_Taipei.jpg)，作者 `╬ಠ益ಠ)`，CC0；EXIF 标记为 sRGB、ISO 1000，已经显影为 JPEG。

±2 EV 检查仅将现有 SDR 图解码为线性 sRGB 后做数值缩放，属于算法压力检查，无法重建过曝 RAW 的高光或传感器阴影。离线一致性测试让两个渲染器接收完全相同的输入；相机预览 ISP、Apple ProRAW 的局部色调/降噪、自动曝光和自动白平衡仍需要真实配对样本确认。后续具备条件时，每类场景应补充锁定机位、曝光和白平衡的预览/RAW 配对，包含不同肤色及中性参照，再决定是否需要相机输入层校准。

## 复现

XcodeBuildMCP 默认项目 `JustShoot.xcodeproj`、scheme `JustShoot`、Debug、iPhone 17 / iOS 26.4.1。使用 `test_sim`，设置 test runner 环境变量 `JUSTSHOOT_SCENE_FIXTURES=<上述目录>/inputs` 与 `JUSTSHOOT_SCENE_EXPORT=<导出目录>`。日常回归没有照片目录时仍覆盖三组确定性合成输入。

导出后执行：

```sh
python scripts/audit_film_scenes.py \
  --samples <上述目录>/inputs \
  --production <导出目录> \
  --output <报告输出目录>
```

Python 依赖为 numpy、Pillow、scikit-image，精确版本记录于 `report.json`。脚本不联网、不拟合曝光、不改写 LUT。核对 `offline-scene-metrics.json` 的输入与资源哈希后再比较两次报告。
