Direction correction
The two Portra color-balance iterations are aesthetic output corrections. They do
not implement Spektrafilm's spectral model, DIR chemistry, statistical grain, or
paper/scanner model. Calling those corrections a core-technology fusion would be
inaccurate. Keep them as a separately evaluated rendering preference.

Core differences and intended transfer
1. Color formation: reconstruct an approximate spectrum from RGB, integrate film
   layer sensitivity, develop layer densities, transmit light through dye spectra,
   expose/develop paper and scan to output RGB. Current Portra uses a different
   spectral model sampled into two density/print tables. Transfer means validating
   these stage responses and calibration, not merely changing orange/cyan grading.
2. DIR chemistry: donor layers inhibit development in receiver layers; spatial
   diffusion makes the correction depend on surrounding density. Current app has
   no corresponding DIR stage. Static local chemistry can be baked into a LUT;
   spatial chemistry requires runtime neighborhood processing.
3. Grain: upstream estimates particle counts from physical pixel/particle area and
   samples density-dependent development statistics, including sublayers. Current
   Portra adds coordinate noise with empirical density weighting before the paper
   transform. Its placement is already useful, but it is not that statistical model.
4. Optics: upstream applies layer-exposure scattering/back-reflection before
   development. Current Portra extracts thresholded highlights from developed SDR,
   blurs and adds tinted energy before its density LUT. Same broad ordering does
   not establish equivalence of the quantities, scale, or energy model.
5. Input: ordinary app capture supplies developed SDR. Inverse sRGB decoding does
   not undo Apple tone mapping or restore clipped highlights. Core migration can
   begin on this explicit domain, but scene-linear exposure/HDR claims require a
   separately calibrated input contract and controlled reference captures.

Observations
The local chemistry visibly changes color separation and saturation. In this
daylight portrait it increases warm coloration; it is not automatically a fix for
the orange cast discussed in the previous tuning iterations. Spatial DIR mostly
changes edge neighborhoods. For neon, mean absolute RGB changes are 4.008/255 for
off->local and 1.623/255 for local->spatial. These measure change, not quality.

The controlled neighborhood test uses two identical RGB=(128,128,128) chips, one
surrounded by code 32 and one by 224, sampled one pixel inside their left edges.
Off/local outputs at the two positions are exactly equal. Spatial DIR outputs
differ by up to 0.101019 in normalized RGB. This directly demonstrates a neighbor-
dependent mechanism that cannot be represented by a single pointwise RGB LUT.
It does not establish that the default spatial strength is aesthetically optimal.
There are no real-film scan references or phone performance measurements here.

Implementation sequence, not yet implemented in production
A. Freeze an upstream reference and create a new explicit material/model identity.
   First implement deterministic color formation + local DIR, keeping experimental
   aesthetic corrections off for reference comparisons. Bake fixed pointwise
   sections offline; use the app's existing GPU table sampling infrastructure.
   Upstream itself supports 1/2/3/4-LUT topologies: LUT use does not remove the core
   model when the baked domain, parameters and intermediate units are preserved.
   The first integration should be a two-stage film-density/print reference path.
   Exposure/log-domain work later needs explicit log-E shapers and domain metadata;
   do not silently put log exposure into existing normalized-density textures.
B. Replace empirical grain with an evaluated mobile statistical approximation:
   preserve density-dependent mean/variance, per-layer size, output-resolution
   scaling, fixed-seed repeatability, and subsequent paper response. Test these
   properties rather than requiring identical random samples to the Python code.
C. Add exposure-domain optics and spatial DIR as separately switchable mechanisms.
   Reuse bounded GPU blur resources where reference agreement allows it; no image
   decoding or profile work per frame. Test edge halos, dark detail, crop/tile
   boundaries, and preview/full-resolution physical-scale consistency.
D. Compare complete native outputs with upstream reference, then enable/tune the
   product's aesthetic layer. Revisit C200/400H after Portra; their current RGB-LUT
   path should not be mislabeled as equivalent density-domain processing.

Acceptance and costs
- Reference agreement: gray/skin/saturated-color probes, controlled exposure ramps,
  and photograph comparisons; first numerical target P95 DeltaE00 <= 0.5 for the
  fixed pointwise reference (a proposed target, not a measured result).
- Material contracts must record input encoding/primaries, model version, exposure
  shaper ranges, density minima/maxima, film/paper/scanner settings and source hashes.
- Preview, still and Live must share the same model/settings; frozen old jobs keep
  their prior material bytes and rendering behavior.
- Two 65^3 RGBA Float32 tables cost 8,788,000 bytes total; four cost 17,576,000 bytes,
  excluding other resources. Four stages also increase cache pressure and sampling.
  Spatial processing adds intermediate work. These are structural costs, not a
  measured phone frame rate. GPU frame time, peak memory and save latency must be
  measured on a physical device before choosing shipping spatial/grain settings.
- Separate code and data provenance/licensing: upstream runtime GPLv3, profiles
  CC BY-SA 4.0. Account for attribution, distribution and any alternative permission
  in the concrete integration route; the app's existing MIT model is a different
  dependency. No upstream runtime code/profile/LUT has been copied into app assets
  by this research step.

Future optimization should prioritize this model-transfer sequence. Reducing orange
cast through additional skin masks alone does not complete that objective.
