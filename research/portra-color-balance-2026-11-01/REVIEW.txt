Portra color balance — 2026-11-01 — current response v2

Intent
Keep JustShoot's tone mapping and warm backlight while borrowing the more restrained
skin color and cooler/warmer shadow separation observed in the Spektrafilm comparison.
This is an independently implemented color preference, not a port, image blend or
measured film calibration. No third-party code, film data or LUT assets are added.

Implementation
New bundled Portra 400 material recipes use neutralRetention=0.72,
skinHueRetention=0.60, skinChromaRetention=0.65, skinResponse=portrait_v2.
The first response used 0.72/0.30/0.35 with no skinResponse.

Encoded-sRGB Y'/Cb/Cr gates compare the material input and its printed, already
portrait-refined output. Low-chroma shadows/midtones retain more input chromaticity;
skin-like colors retain part of their input hue and reduce excess output chroma.
The first gate missed muted red/pink hues visible in the deep-skin daylight photo.
V2 moves the lower hue-ratio ramp from 0.35–0.55 to 0.08–0.35, retains the upper
hue/chroma/brightness gates, and strengthens partial hue/chroma retention. This is
not face detection: wood, clothing, flowers and similar warm lights can also change.

Chroma cannot exceed the prior output. Gamut bounds compress chroma toward the same
Y' rather than clipping channels. The correction fades out toward bright warm light;
black/white endpoints and saturated blue/green/red/cyan probes stay unchanged. V2
keeps v1's neutral-shadow behavior when the skin gate is inactive.

The correction preserves encoded-sRGB weighted luma before user curves/headroom.
This does not assert unchanged perceptual brightness, linear-light luminance or
post-curve luma for a non-neutral per-channel user curve. There is no new exposure
adjustment, highlight compression, blur, sharpening or recovery of clipped SDR detail.
Existing highlight flatness is not solved by this color-only change.

The shared helper runs inside existing preview/Core Image finish passes, after
print/refinement and before user curves. Density/print tables, diffusion, grain,
bundled LUT bytes and other presets are unchanged. No additional texture lookup,
GPU pass, image decode or per-frame I/O is introduced. Additional arithmetic has
not been benchmarked on a physical device.

Compatibility
The current Portra cache key ends in #color-balance-v2. Codable parameters and the
optional skinResponse are frozen with material bytes in the capture journal.
Missing colorBalance bypasses the helper. A balance without skinResponse retains
the v1 gate. The bare material key resolves without a balance; #color-balance-v1
resolves with the original 0.72/0.30/0.35 parameters. Frozen RGB-only recipes and
custom LUTs keep their prior path. Material schema and table identifier remain v1.

Archived baseline verification
The unbalanced original matches all 18 earlier color/full decoded RGB images.
V1 matches all nine archived color-only images exactly. Six full-effect images
also match; daylight portrait, sunlight cafe and night cafe each differ in one
channel sample by one 8-bit code value. These differences are recorded rather than
reported as complete pixel identity. PNG bytes are not used as a pixel proxy.

The maximum absolute v2-v1 weighted-luma difference across encoded images is below
one 8-bit code value (0.9542); float tests verify the correction before encoding.
These metrics quantify change and baseline agreement, not visual quality.

Focused regression coverage
- Gray ramp: neutral shadow cast reduced; prior luma and gray separation retained.
- Four warm skin shades retain partial film hue without added chroma or darkening.
- Four muted red/warm probes reduce input-relative hue error beyond v1 without
  increasing chroma or changing luma.
- A 257-sample skin-to-white highlight ramp retains previous luma differences;
  colors at source Y' >= 0.90 retain the prior RGB output.
- A 17-cubed color volume stays finite, in gamut and within 2e-6 of prior Y'.
- Frozen bare-material/v1/v2 keys and payloads retain their respective responses;
  missing/invalid parameters and corrupted material payloads are covered.
- Density model, capture journal/recovery, WB/curve and preview/still/Live checks pass.

Visual review and limits
Deep-skin daylight forehead/nose/cheek look less orange-red than v1. Window portrait
loses some excess warm saturation, but its bright/flat face and red-brown hair are
still limitations. Backlit gold remains visible while facial orange is reduced.
Forest changes very little; muted warm colors in neon, flowers and cafe can change.
This is a restrained improvement, not evidence that JustShoot universally beats
Spektrafilm. The spectral reference retains its original exposure/scanner sharpening;
its darker blacks and stronger sharpening are not matching targets. No physical
film scans, new device captures or physical-device performance measurements were
available for this review.
